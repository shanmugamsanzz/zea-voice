# Callback and reminder scheduling

Agents with Customer Callback enabled can use the authorized `manage_follow_up` tool during inbound or outbound phone conversations. The same agent must allow outbound usage (Both for inbound callbacks). Browser tests do not schedule phone calls. Requests apply to the current caller's normalized number and company/workspace; the tool cannot choose another recipient.

An explicit request such as "call me in 10 minutes" schedules immediately. Absolute times first produce a proposal; the agent must clarify the date, AM/PM and IANA timezone and obtain a later confirmation of that exact proposal. Invalid dates, unknown timezones, nonexistent or ambiguous daylight-saving times require clarification. The configured callback minimum delay and maximum window still apply. A summary mentioning a callback does not schedule one.

Standalone callbacks and reminders are persisted until due, then enter the existing phone-test outbound queue atomically. They count toward the company's outbound waiting limit before dispatch. Dispatch preserves credit, account, phone assignment and shared capacity checks, and waits while the same contact has an active conversation. The scheduled time is the earliest dispatch time; available capacity and queue order can delay it. A standalone task has one dialing attempt by default; ambiguous provider results are not automatically redialed.

Campaign calls retain the original campaign task, queue, schedule and retry allowance. A requested callback consumes one existing retry; a conversation follow-up record mirrors that task rather than creating a second dial. The worker retries delivery of due persisted mirrors with the same campaign job identifier when queue delivery was unavailable. Campaign follow-up outcomes follow the campaign task's final result.

Caller requests can cancel pending follow-ups through the tool. Super Admin and Company Developers can cancel Scheduled/Queued tasks from Conversations; Company Users have read access. Cancellation does not stop an already dispatched call or refund a consumed campaign retry. Company/workspace checks, live-call authorization, caller evidence, request keys and database uniqueness protect against unauthorized or duplicate scheduling. Attempt links and signed hangup callbacks track completed, busy, no-answer, canceled and failed outcomes without merging call transcripts or billing records.

Company queue rollout also uses `VOICE_COMPANY_QUEUE_ENABLED` and `VOICE_COMPANY_QUEUE_TENANT_IDS`; the existing campaign workers and phone-test queue tick perform dispatch. Keep queue workers enabled. Existing agent callback settings control availability.

Local fixtures cover time resolution, confirmation, duplicate requests, company isolation, cancellation, due transfer and outcome linking. Actual PostgreSQL migrations/triggers, Redis queue recovery, provider callbacks and concurrent cancellation/dispatch must also be verified in staging before production rollout.
