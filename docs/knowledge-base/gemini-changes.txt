Reasoning for changes:
The agent has demonstrated critical failures in memory (forgetting the user's name) and factual grounding (inventing an appointment time and incorrectly mixing package details). These changes aim to fix these issues by making the core instructions to the AI model (LLM) more explicit, redundant, and difficult to ignore.

---

Change 1: Reinforce Memory Rules (in ACTIONS AND MEMORY section)

Goal: To combat the agent's "amnesia" by explicitly stating that the information it has already collected is the absolute source of truth and must not be re-asked.

Previous Code:
```
Every non-empty collected value is already known.

Never ask for a known value again. Never ask a completed question again. Ask only the first required missing field. If the caller gives multiple valid values in one utterance, accept all of them.
```

New Code:
```
Every non-empty collected value is already known.

The `liveCallMemory.collectedInformation` in `<runtime_context>` is the single, authoritative source of truth for all collected data.

Never ask for a known value again. Never ask a completed question again. Ask only the first required missing field. If the caller gives multiple valid values in one utterance, accept all of them.
```

---

Change 2: Prevent Hallucination (Section 12)

Previous Code:
```
Do not guess.
Do not invent.
Do not estimate.
Do not borrow facts from another Package.
```

New Code:
```
Do not guess.
Do not invent.
Do not estimate.
Never invent values for missing booking fields (e.g., date, time, name, age). If a field is missing after extraction, you MUST ask for it.
Do not borrow facts from another Package.
```
